This project uses the standard .NET SDK build system with MSBuild via a single `Agentic.ACPLibrary.csproj` file and automates packaging/publishing through a GitHub Actions workflow.

**Build system**: The project targets `net10.0` with implicit usings and nullable enabled. It is marked as packable (`IsPackable=true`) and configured entirely in the `.csproj` — no separate `Directory.Build.props`, `global.json`, or Makefiles are used. Dependencies are declared directly in the project file via `PackageReference` entries for `Microsoft.Extensions.DependencyInjection.Abstractions`, `System.Text.Json`, and `Microsoft.Extensions.Logging.Abstractions` (all version 10.0.10).

**Packaging**: `dotnet pack` is invoked against `Agentic.ACPLibrary.csproj` in Release configuration, outputting to `./nupkg`. The package includes `README.md` and `LICENSE` as embedded assets. Versioning is driven by `<VersionPrefix>0.1.0</VersionPrefix>` in the project file; CI appends a nightly suffix using `-p:VersionSuffix=nightly.${{ github.sha }}` so each push on `main` produces a unique pre-release package.

**CI/CD pipeline**: `.github/workflows/nuget.yml` runs on every push to `main` on a `windows-latest` runner. It authenticates to both nuget.org (via `NuGet/login@v1` with an API key) and GitHub Packages (via a bot token stored in secrets), then pushes the built `.nupkg` to both feeds. No tests are run in the pipeline — only pack-and-publish.

**Conventions & constraints**:
- All build metadata lives in the single `.csproj`; there is no shared props/targets or multi-project solution.
- Version bumps must be edited directly in the `<VersionPrefix>` property.
- Nightly builds use commit SHA-based suffixes to guarantee uniqueness; stable releases would require pushing a tag or changing the trigger logic.
- The pipeline assumes .NET 10.0.x is available on the runner and that `NUGET_USER`, `NUGET_API_KEY`, and `BOT_TOKEN` secrets/variables are configured.
