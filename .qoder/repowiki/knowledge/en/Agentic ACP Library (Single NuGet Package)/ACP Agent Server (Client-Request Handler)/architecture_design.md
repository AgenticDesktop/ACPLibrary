The module implements the server half of the ACP protocol. `IAcpAgent` is the lifecycle interface (`RunAsync`/`StopAsync`/`IsRunning`) implemented by `AcpAgent`, which owns an `IAgentTransport`, an `IJsonRpcDispatcher`, and an `IAcpAgentHandler`. On `RunAsync`, the transport is started, the dispatcher is connected, and four request/notification routes are registered: `initialize`, `session/new`, `session/prompt`, and `session/cancel`. Each route deserializes its payload via `System.Text.Json`, delegates to the corresponding `IAcpAgentHandler` method, and wraps exceptions in a standard `JsonRpcError(-32603)`. Active sessions are tracked in a `ConcurrentDictionary<string, CancellationTokenSource>` keyed by sessionId so `session/cancel` can cancel the right token. `IAcpAgentContext` defines the outbound API (session updates, permission requests, file I/O, terminal management); `AcpAgent` provides a private nested `AcpAgentContext` implementation that forwards calls through `_dispatcher.SendNotificationAsync` / `SendRequestAsync` using the same JSON-RPC naming convention (e.g. `session/update`, `fs/read_text_file`, `terminal/*`). `IAcpAgentHandler` is the extension point for application logic, with `AcpAgentHandlerBase` supplying sensible defaults (protocol version 1, GUID session IDs, no-op cancel) so implementers only override `HandlePromptAsync`.
