This repository uses the standard .NET SDK-style project system for dependency management, with all third-party packages declared in a single `Agentic.ACPLibrary.csproj` file. There is no `packages.config`, `global.json`, or `Directory.Packages.props` — dependencies are managed inline via `<PackageReference>` elements.

**Packages and versions**
The project targets `net10.0` (preview) and declares three direct dependencies, all pinned to version `10.0.10`:
- `Microsoft.Extensions.DependencyInjection.Abstractions` — DI abstractions used by `Infrastructure/ServiceCollectionExtensions.cs`
- `System.Text.Json` — JSON serialization for JSON-RPC messages (`JsonRpcMessageConverter`, `JsonOptions`)
- `Microsoft.Extensions.Logging.Abstractions` — logging abstraction used throughout the library

No lockfile (`.csproj.lock`) or `packages.lock.json` is present in the repo; package resolution is left to the local/global NuGet cache.

**Packaging and publishing**
- The project is marked `<IsPackable>true</IsPackable>` with `PackageId`, `VersionPrefix`, authors, description, tags, license, and repository metadata defined directly in the `.csproj`.
- A GitHub Actions workflow (`.github/workflows/nuget.yml`) builds the package on push to `main`, pushes nightly builds to both nuget.org and GitHub Packages using API keys/secrets from GitHub variables.
- Published packages include `README.md` and `LICENSE` as embedded assets.

**Conventions and constraints**
- All dependencies use exact major.minor.patch versions (no `*` or range operators), ensuring reproducible builds at the source level.
- No private NuGet sources are configured in the project itself; the CI workflow adds GitHub Packages as an additional source at runtime.
- The project does not vendor dependencies — they are resolved at build time from NuGet feeds.
- Target framework is locked to `net10.0`; there is no multi-targeting configuration.
